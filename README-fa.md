# turkish-data-validation — اعتبارسنجی داده‌های ترکیه‌ای در کد

**لایهٔ ایجنتی که اعتبارسنج‌های ترکیه‌ای نداشتند.**

هر فرم ترکیه‌ای، هر ایمپورت دادهٔ مشتری و هر فیکسچری که ایجنت
می‌نویسد با همان شناسه‌ها سروکار دارد — TCKN، VKN، IBAN، تلفن،
پلاک، کد پستی — و ایجنت‌ها آن‌ها را با حدس اعتبارسنجی می‌کنند.
حدس‌ها به شکل‌های مشخص و تکرارشونده غلط‌اند: TCKN که فقط با طول
چک شده (۱۱ رقم کافی نیست — دو رقم آخر چک‌سام‌اند)؛ VKNای که از یک
بلاگ کپی شده و رقم کنترلی‌اش غلط است؛ IBANای که دو رقمش جابه‌جا
شده و هیچ regexای نمی‌گیردش؛ شماره تلفنی که بدون کد کشور ذخیره
شده؛ `"istanbul".upper()` که `"ISTANBUL"` می‌دهد (قاعدهٔ انگلیسی —
فرم ترکی `"İSTANBUL"` است)؛ مبلغی که `"1,250.50 ₺"` نوشته شده
(جداکننده‌های انگلیسی — ترکی `"1.250,50 ₺"` است).

## چه چیزی را چک می‌کند

| کد | چک | مثال |
|------|-----|------|
| TDV-01 | TCKN (۱۱ رقم، دو چک‌سام) | 10000000146 معتبر؛ 10000000145 رقم یازدهمش غلط است |
| TDV-02 | VKN (۱۰ رقم، یک چک‌سام) | 1234567890 معتبر؛ 0010048920 غلط است (چک باید ۶ باشد) |
| TDV-03 | IBAN ترکیه (TR + ۲۴ رقم، mod-97) | TR33 0006 1005 1978 6457 8413 26 معتبر؛ TR32… در mod-97 رد می‌شود |
| TDV-04 | تلفن ترکیه (موبایل / ثابت / 444 / 0850 / 0800) | +90 532 123 45 67 ← +905321234567 |
| TDV-05 | پلاک (کد استان ۰۱–۸۱) | 34 AB 123 ← استانبول؛ 99 AB 123 نامعتبر |
| TDV-06 | کد پستی (۵ رقم، دو رقم اول کد استان) | 34000 ← استانبول؛ 99000 نامعتبر |

فرمت‌کننده‌ها: پول (`1250.5` ← `1.250,50 ₺`)، تاریخ
(`2026-11-18` ← `18.11.2026`)، حروف ترکی (`istanbul` ←
`İSTANBUL`).

## نصب

**Claude Code / Claude.ai** — پوشهٔ اسکیل را کپی کنید یا فایل
`dist/turkish-data-validation-skill.zip` را آپلود کنید:

```bash
cp -r skills/turkish-data-validation ~/.claude/skills/
```

**Cursor** — فایل `cursor/turkish-data-validation.mdc` را در
`.cursor/rules/` پروژه‌تان بگذارید (برای Windsurf و Cline و
Continue به `cursor/README.md` نگاه کنید).

**MCP** — سرور stdio در `mcp-server/` این ابزارها را می‌دهد:
`validate_turkish_data`، `detect_turkish_data`،
`format_turkish_data`، `generate_turkish_test_data`،
`audit_turkish_csv` و `list_turkish_checks`.

**استفادهٔ مستقیم** — بدون نصب و بدون وابستگی (فقط stdlib
پایتون ۳٫۹ به بالا):

```bash
python3 skills/turkish-data-validation/scripts/turkish_data_validation.py validate tckn 10000000146
python3 skills/turkish-data-validation/scripts/turkish_data_validation.py audit customers.csv --column tckn
```

## راستی‌آزمایی

- **۹۲ تست پاس می‌شوند** (`pytest tests/`): همهٔ کدهای چک با
  بردارهای معتبر/نامعتبر، مثال‌های منتشرشده، رفت‌وبرگشت
  ژنراتور، فرمت‌کننده‌ها (از جمله تلهٔ حروف ترکی)، ابهام‌زدایی
  `detect`، کدهای خروجی CLI، خروجی JSON، فیکسچر حسابرسی CSV و
  تست سرتاسری MCP.
- الگوریتم VKN با بردارهای منتشرشده راستی‌آزمایی شد — نسخهٔ اول
  الگوریتم 1234567890 را رد می‌کرد و بردارهای تست پیش از انتشار
  گرفتندش.
- جدول ۸۱ استان نام‌به‌نام با یک منبع مستقل چک شد (هر ۸۱ نام
  مطابقت دارد).

## چه کاری نمی‌کند

- هویت را اثبات نمی‌کند. چک‌سامِ قبول‌شده فقط سازگاری ارقام را
  نشان می‌دهد — نه صدور و نه تعلق به کسی. فقط مرجع صادرکننده
  می‌تواند تأیید کند.
- محله و خیابان را نمی‌داند (کد پستی تا استان می‌رسد).
- پیش‌شمارهٔ موبایل را به اپراتور نگاشت نمی‌کند — با جابه‌جایی
  شماره (portability) آن نگاشت سال‌هاست نامعتبر است.
- MERSIS و SGK را اعتبارسنجی نمی‌کند (نقشهٔ راه).
